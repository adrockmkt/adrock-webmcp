# v0.6.6 Automated Sync Validation

Status: VALIDATED

Date: 2026-09-25

## Objective

Keep the public WebMCP discovery index and normalized article store synchronized with the public Ad Rock blog, then rebuild and deploy the GitHub Pages runtime when generated content changes.

## Validated pipeline

1. Discover public `/blog/*` URLs from the Ad Rock sitemap.
2. Extract article metadata with bounded retry and exponential backoff for transient empty responses.
3. Fail closed when extraction contains errors or unexpected skipped pages.
4. Generate `data/blog-index.generated.json`.
5. Generate the normalized per-slug article store and manifest.
6. Validate index and article-store consistency.
7. Detect generated content changes.
8. Commit generated public content atomically.
9. Build the dynamic blog search runtime.
10. Prepare and upload the GitHub Pages artifact.
11. Deploy the runtime to GitHub Pages.

## Resilience validation

A scheduled run on 2026-09-25 exposed a transient Framer/CDN response for:

`google-data-manager-vs-zapier-vs-make-vs-hubspot`

The response contained a valid URL and slug but empty editorial metadata. The sync correctly failed instead of publishing an incomplete index.

The generator was hardened to:

- use up to five attempts for HTTP/network failures or fully empty article metadata;
- use exponential backoff between attempts;
- avoid retrying known structural pages that already contain metadata but have no publication date;
- promote persistently empty article metadata to an explicit error;
- write the generated index only after the generation is considered publishable.

Local regression tests passed 8/8.

- errors: 0
- publishable: true
